# 项目使用助手（怎么跑起来 / 怎么排查）

这是整个仓库的**操作手册**：怎么启动、怎么看日志、怎么部署、怎么排查。
按「你在哪一端」查对应章节即可。命令和路径都来自仓库真实结构，不写死密码 / IP。

## 1. 环境准备

| 依赖 | 用途 | 验证 |
|---|---|---|
| Flutter SDK | 桌面端 | `flutter --version` |
| Node 20+ | 抖音 a_bogus 签名子进程、admin-web 构建 | `node -v` |
| Python 3.10+ | 统一服务端 | `python3 --version` |

### .env 配置（服务端）

完整 `.env` 模板见 [docs/env-template.md](env-template.md)，复制粘贴后把占位符改成真实值。
关键必填：`DB_*`（连库）、`JWT_SECRET`（登录安全）、`ADMIN_PASSWORD`（后台密码）。

`.env` 不进 git。改密码/端口只改 `.env`，重启服务生效。

## 2. macOS 本地跑桌面端

```bash
cd /Users/huoyz/project/4KDownle/apps/desktop
flutter pub get
flutter run -d macos --dart-define=API_BASE=http://8.153.99.239:3000
```

- 开发态 yt-dlp / ffmpeg 走系统 PATH（找不到时自动探测 `/opt/homebrew/bin` 等）。
- 首次运行会从 `assets/bin/` 提取二进制到应用支持目录。
- 常见启动报错：
  - 引擎未就绪 → 没装 ffmpeg/yt-dlp：`brew install ffmpeg`，yt-dlp `brew install yt-dlp`
  - 连不上后端 → 检查 `API_BASE` 和服务器安全组放行 3000

### 桌面端日志在哪（重要）

打包版双击启动没有控制台，`debugPrint` 会被写到文件：

- **macOS**：`~/Library/Application Support/com.example.downieTest/logs/app_YYYYMMDD.log`
- **Windows**：`%APPDATA%\com.example.downieTest\logs\app_YYYYMMDD.log`（或安装目录附近）

按天一个文件。排查「打包后不工作」就看这个文件，别只看控制台。

## 3. 桌面端打包 + 排查

```bash
cd apps/desktop
flutter build macos    # 产物：build/macos/Build/Products/Release/4KDownle.app
flutter build windows  # 产物：build/windows/x64/runner/Release/
```

**打包前必查**：`assets/bin/{macos,windows}/` 下的 ffmpeg + yt-dlp 是否在。
这两个二进制被 .gitignore 忽略、不进库，CI 会自动下载；本地打包要自己放进去。

**打包后排查清单**：
1. 双击打开，看日志文件（§2 的路径）有没有 `引擎未就绪` / `提取失败`
2. 图标 / logo 没进包 → 重新跑 `bash tools/generate_icons.sh`
3. 内嵌二进制没提取 → 检查 `assets/bin` 是否为空（开发态为空会回退 PATH，打包版不会）

## 6. 服务端运行与部署

### 6.1 首次部署（服务器上，完整顺序）

```bash
# 1. 拉代码
cd <仓库目录> && git pull origin main

# 2. 装 Python 依赖
cd services/api
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 3. 装系统依赖（视频处理 + 抖音签名）
apt install -y ffmpeg nodejs

# 4. 配 .env（完整模板见 docs/env-template.md）
vim .env

# 5. 建表 + 种子：进 Docker MySQL 容器手动执行（见 §9）
docker exec -i mysql-mysql-1 mysql -uroot -p <数据库名> < sql/init_all.sql

# 6. 停旧 Node 服务（还占着 3000 端口的话）
pm2 stop downie-license-api

# 7. 前台测试启动
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 3000
```

### 6.2 验证后切 pm2 守护

前台启动 OK（`curl http://127.0.0.1:3000/health` 返回 `{"status":"ok",...}`）后，Ctrl+C 停掉，改用 pm2：

```bash
cd services/api
pm2 start ".venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 3000" --name api
pm2 save
pm2 startup     # 按它输出的那条命令执行，实现开机自启
```

### 6.3 本地调试

```bash
cd services/api
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload        # 默认 3000
```

- 只跑媒体模块（不连 MySQL）：`MODULES=media uvicorn app.main:app --port 8000`
- 健康检查：`curl http://127.0.0.1:3000/health`

### 6.4 看日志（服务器）

```bash
pm2 logs api                 # 实时
pm2 logs api --lines 100     # 最近 100 行
pm2 logs api --err           # 只看错误
```

日志内容：解析/下载/去水印关键步骤、未捕获异常堆栈、MySQL/Redis 连接失败。

## 7. 常见问题排查

| 现象 | 排查 |
|---|---|
| 端口被占用 | `lsof -i :3000`，换 `PORT` 或杀掉占用进程 |
| MySQL 连不上 | `.env` 的 `DB_HOST/PORT/USER/PASSWORD/NAME`；`mysql -h127.0.0.1 -u... -p...` 手动试 |
| Redis 连不上 | `redis-cli ping` 应回 `PONG`；查 `REDIS_HOST/PORT/PASSWORD` |
| 抖音解析失败 | 服务器没装 `node`（a_bogus 签名要起 node 子进程） |
| 视频处理报错 | 没装 `ffmpeg`/`ffprobe`；`PIL` 报错 → `pip install Pillow`（旧 requirements 漏过） |
| 下载/解析 403 | 签名 URL 过期或 `sig` 不匹配（`SIGNED_URLS=1` 时 `/files` `/tmp` 要带签名） |
| CORS 报错 | `.env` 的 `ALLOWED_ORIGINS` 白名单没包含前端域名 |
| 打包后桌面端不工作 | 看日志文件（§2），不是看控制台 |

## 8. 管理后台（pure-admin-vue3）

后端接口全部走 `/login` `/get-async-routes` `/user` `/role` `/menu` `/dept` `/card/*` `/task/*`（无 `/api` 前缀）。
默认管理员：`admin` / 初始密码 `admin123`（登录后到「用户管理」改）。

### 8.1 本地开发

```bash
cd apps/admin-web
pnpm install
pnpm dev          # 开发态，vite 已把 /login /user /card 等代理到 http://127.0.0.1:3000
```

浏览器打开 `http://localhost:8848`。

### 8.2 部署到服务器（构建 → 上传 → 重启）

构建产物由后端的 `/admin` 静态挂载托管，所以三步：

```bash
# 1. 本地构建（构建时 base 强制 /admin/，产物在 dist/）
cd apps/admin-web
pnpm build

# 2. 上传 dist 到服务器
ssh root@<服务器IP> "mkdir -p <仓库目录>/services/api/static/admin"
scp -r dist/* root@<服务器IP>:<仓库目录>/services/api/static/admin/

# 3. 重启服务（/admin 挂载是启动时判断的，改了静态文件必须重启）
ssh root@<服务器IP> "pm2 restart api"
```

访问 `http://<服务器IP>:3000/admin/`。

> 常见坑：如果访问 `/admin/` 返回 404，先查两点——
> ① `services/api/static/admin/` 里有没有 `index.html` 和 `static/` 目录（说明 dist 没传对）
> ② 有没有 `pm2 restart api`（静态挂载只在启动时读一次目录）

- 建表 + 种子数据：见 §9（进 Docker MySQL 容器执行 `init_all.sql`）。

## 9. 阿里云服务器：进 Docker MySQL 容器手动建表

> MySQL 跑在阿里云服务器的 Docker 里，**3306 没对外开**，所以只能在**服务器上**操作，不能在自己电脑连。
> 建表 + 种子数据都在一个脚本里：`services/api/sql/init_all.sql`（幂等，可重复跑）。

### 9.1 前置：把脚本弄到服务器

```bash
ssh root@<服务器IP>              # 1. 登录服务器
cd <你部署的仓库目录>            # 2. 进仓库，例如 ~/4KDownle
git pull origin main            # 3. 拉最新代码，脚本在 services/api/sql/init_all.sql
```

### 9.2 第一步：看 MySQL 容器叫什么名

```bash
docker ps
```

看输出里 **NAMES** 那一列，就是容器名（老项目叫 `mysql-mysql-1`，下面都用它举例）。

### 9.3 第二步：进入 MySQL 并登录

```bash
docker exec -it mysql-mysql-1 mysql -uroot -p
```

这条命令拆开看：
- `docker exec -it 容器名` = 进入这个容器执行命令（`-it` 交互式，能输入）
- `mysql -uroot -p` = 用 `root` 用户登录 MySQL，`-p` 表示接下来要输密码

回车后出现 `Enter password:`，**输入 MySQL root 密码**（输入时屏幕不显示任何字符，这是正常的，直接输完回车）。

登录成功后，提示符会变成 `mysql>`。

### 9.4 MySQL 常用命令（每个是干嘛的）

在 `mysql>` 提示符下输入，**每条结尾必须带分号 `;`**：
这个命令进容器，不带--default-character-set=utf8mb4会乱码，中文名复制不进去
docker exec -it mysql-mysql-1 mysql -uroot -pNjcb@a1p --default-character-set=utf8mb4 downie_db  

| 命令 | 作用 |
|---|---|
| `SHOW DATABASES;` | 列出所有数据库，找你的库名（对应 `.env` 的 `DB_NAME`） |
| `USE 库名;` | **进入**某个数据库（进库命令） |
| `SELECT DATABASE();` | 查看当前在哪个库 |
| `SHOW TABLES;` | 列出当前库里的所有表 |
| `DESC 表名;` | 查看某张表的结构（有哪些字段、类型） |
| `SELECT * FROM 表名;` | 查表里所有数据 |
| `SELECT username FROM sys_users;` | 查指定字段 |
| `exit` 或 `\q` | 退出 MySQL（退出后回到服务器命令行） |

### 9.5 执行建表脚本（两种方式任选）

**方式 A（推荐，宿主机一条命令，不用拷文件）** —— 退出 MySQL（`exit`）回到服务器命令行后：

```bash
cd services/api
docker exec -i mysql-mysql-1 mysql -uroot -p <数据库名> < sql/init_all.sql
```

- `<数据库名>` 换成 `.env` 的 `DB_NAME`
- 回车后输 root 密码
- 这条命令把 `init_all.sql` 的内容通过管道喂给容器里的 `mysql`，建表 + 写种子一次完成

**方式 B（先把脚本拷进容器，再进 MySQL 里 source）**：

```bash
# 1. 把脚本从宿主机拷进容器
docker cp services/api/sql/init_all.sql mysql-mysql-1:/init_all.sql

# 2. 进容器登录 MySQL（并直接指定库，省得再 USE）
docker exec -it mysql-mysql-1 mysql -uroot -p <数据库名>

# 3. 登录后（mysql> 提示符）执行脚本
source /init_all.sql;
```

### 9.6 核对是否成功

```sql
SHOW TABLES;                       -- 应有 9 张表
SELECT id, username, nickname FROM sys_users;   -- 应有一行 admin
SELECT id, title FROM sys_menus;   -- 应有 8 条菜单
```

9 张表分别是：`licenses`、`device_bindings`、`unbind_log`（授权）+ `sys_users`、`sys_roles`、`sys_menus`、`sys_role_menus`、`sys_user_roles`、`sys_depts`（后台 RBAC）。
